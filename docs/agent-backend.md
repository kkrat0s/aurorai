# Observation coordinator and private backend

Implemented on 2026-10-28. This document separates working local code from integration gates.

## Working local workflow

`@aurorasense/coordinator` exports the seven typed tools, `createCoordinator`, `validateRegional`, `createDemoState`, and `runDemoCoordinator`. Model tool arguments cannot supply an actor, role, event, clock or run ID: a trusted caller supplies that context once. Public/volunteer roles cannot invoke research orchestration. Arguments are strict Zod objects; unauthorized cells, unknown sources, future intervals and cross-session access fail closed and create a blocked audit action.

The web's replay calls `runDemoCoordinator()` in memory. It deliberately uses synthetic fixtures and a scripted sequence, **not Muse Spark**. A local-interference fixture is rejected; a simulated opted-in adult receives an in-app invitation record; a synthetic completion is ingested; the final verdict remains `INCONCLUSIVE`. There are zero real usable sites. Five repeated resets produce exactly the same timeline, assessment and report. The fixed clock is a logical demo clock, not measured execution latency. No email, notification or remote sensor activation is sent.

`run_local_qc` reads the acquisition QC report and independently checks its series schema and time. The foreground recorder's high-rate algorithm resides in `packages/shared/src/sensor.ts`. The coordinator consumes trusted derived scalar summaries; it does not ask the LLM to calculate sensor quality. Integrating real recorder exports into minute scalar summaries is still required before a phone record may enter regional validation.

## Deterministic scientific policy

The versioned `regional-scalar-v1.0.1` policy compares baseline-subtracted scalar F in nT. It does not compare device X/Y/Z to geographic station axes. Its provisional criteria require at least three independent real phone sites, at least 20 km separation, separate local interference groups, a professional scalar reference within 500 km, at least eight exactly aligned UTC minute bins spanning at least seven minutes, no gap over 90 seconds, endpoint coverage within two minutes, correlation at least 0.7, and within-window central-80% excursion at least max(100 nT, five times baseline noise). Reference excursion must also exceed 100 nT. Constant baseline offsets and dense subsecond bursts cannot satisfy those criteria. Timestamp strings are parsed as UTC instants; no post-hoc lag search is performed.

These are conservative engineering screening criteria, **not empirically calibrated storm sensitivity or false-alarm guarantees**. Co-located/shared-environment devices form connected groups. All in-scope evidence is checked even if a model requests a favorable subset. Synthetic data cannot support a real regional claim. Unknown/later availability fails operational analysis; retrospective analysis states its availability limitation. `SUPPORTED` means consistency with a regional magnetic disturbance under these rules, never optical aurora or direct reconnection measurement.

Publication ignores free-form model prose and generates a canonical statement from the current deterministic assessment. Adding evidence invalidates the previous assessment. Synthetic public reports require review. Local research publication creates an in-memory report; it does not publish a website. Audits expose sequence, prior action ID, UTC, tool, status, mode and argument fingerprint. The local fingerprint detects changes; it is **not** a cryptographic signature. Durable journals use SHA-256 and an append-only database trigger.

## Muse Spark adapter

The server-only `@aurorasense/coordinator/meta` export implements the official Responses wire format at `https://api.meta.ai/v1/responses` with `muse-spark-1.3` (Standard, not Contributor). It uses `store:false`, stateless output/function-call continuation, encrypted reasoning replay, validated function arguments, five model rounds, at most seven tool calls per round, 1,500 output tokens per request, an 80 KB request bound and a 25-second network timeout. Multiple requested tools execute sequentially through authorization. Model failures, rate limits, incomplete outputs and exhausted budgets produce explicit unfinished states; there is no unbounded automatic retry.

Official references verified on 2026-10-28: [Responses endpoint](https://dev.meta.ai/docs/api-reference/responses/create-response), [request/response schemas](https://dev.meta.ai/docs/api-reference/responses/schemas), [Standard mode and pricing](https://dev.meta.ai/docs/pricing-rate-limits). The adapter currently estimates uncached input at $1.25/M tokens and output at $4.25/M tokens; update and review these constants if provider pricing changes. Standard's training policy does not mean zero retention. `store:false` is not a blanket zero-retention promise.

Real runs require a durable budget ledger and run journal. `@aurorasense/coordinator/supabase` supplies both through managed Supabase REST. Reservations are atomic PostgreSQL RPCs; uncertain failures keep their reserved cost. The coordinator allocation is capped at $45 total, $5 per UTC day, 100 calls per UTC day and 1,000 total calls. This leaves other approved grant allocations untouched. Each reservation uses a conservative UTF-8-byte input-token upper bound plus envelope allowance and output cap. Duplicate request IDs are refused. Never run other model experiments against this ledger as if it were the entire project budget. A trusted server may separately authorize `syntheticParticipantsAllowed` for a genuine model call over a clearly labeled simulated participant workflow; execution mode and participant provenance remain separate.

**No credentialed Meta request has been made or tested in this session.** Transport tests use mocks and return `MOCK_TRANSPORT`. The implemented `/api/agent` route is not deployed or credentialed. The web currently offers the explicitly scripted replay. Model latency, actual billable usage, genuine tool choice and actual follow-up behavior remain unmeasured.

## Authenticated application route

`POST /api/agent` accepts only `{ "eventId": "..." }` and a Bearer access token. Missing server configuration returns 503 `AGENT_NOT_CONFIGURED` before any network call. The request stream is capped at 2,048 bytes with early cancellation and a five-second read deadline; malformed or negative Content-Length is rejected. It verifies the token with Supabase `auth/v1/user`, requires the admin-controlled `app_metadata.aurorasense_role` to equal `researcher`, takes permitted cells only from `app_metadata.aurorasense_cells`, and reads adult consent/version through the user's authenticated RLS context. User-editable metadata and body-supplied identity/evidence are ignored or rejected.

The server then loads the stored event and authorized per-event `regional_summary` records from server-owned `sensor_qc` and `reference_series`. Migration `202610280003_regional_inputs.sql` adds those fields and lookup indexes. Each summary must pass the minute-scalar schema; phone IDs, quality decisions and algorithm versions must match persisted acquisition QC. Reference IDs must match their database row and linked source identity, kind, URL and SHA-256 checksum. No synthetic record is accepted on this route. Missing summaries or unapplied migrations return 409 `NEEDS_INGESTION`; the route never substitutes replay fixtures. Raw high-rate uploads and browser-supplied evidence are not model inputs.

With valid records, the route starts a five-round Spark run using the durable Supabase budget and journal. The seven tools expose compact metadata/QC/counts/correlations/canonical reports, never raw coordinates or volunteer user IDs. The HTTP response additionally strips private coordinate/identity keys recursively and redacts all known participant IDs, including inside nested action results. It returns only canonical reports, safe tool output, usage and status. Private run snapshots remain in the private journal. Public report requests require review; this route does not publicly publish a site or evidence record. Real participant invitations are deliberately blocked with `INVITATION_DELIVERY_NOT_CONFIGURED` until transactional campaign persistence, delivery and acceptance are wired. The synthetic replay continues to demonstrate this branch without pretending a volunteer was notified. A complete credentialed real gap → invitation → participant response loop therefore remains an integration gate.

## Supabase migrations

`202610280001_initial.sql` creates source/event/forecast/reference metadata, participant consent, private sessions/chunks/QC, aggregated coverage, campaigns/invitations, provisional observations, model runs, append-only actions and evidence reports. `202610280002_budgets.sql` creates the atomic budget RPCs and append-only run journal.

All tables enable RLS, revoke default anonymous/authenticated rights, then grant narrowly scoped access. Participants can read/delete their own raw metadata and insert only with adult recording consent. Client writes cannot assert QC acceptance, verification, model scores or evidence reports. Public reference/source reads require approved rights metadata. Public coverage suppresses fewer than three independent sites. No precise participant coordinates are in the public tables. The `sensor-raw` bucket is private, permits only JSON up to 2 MiB, scopes paths to owner/session, and has no update policy. Original bytes remain immutable while owner deletion is permitted. Private photos and public EXIF processing are not implemented.

**Neither migration nor hosted RLS tests have been executed against Supabase.** No local `psql` or Supabase CLI was found. `supabase/tests/rls.sql` is a transaction-scoped pgTAP suite for an isolated Supabase test project. It tests cross-user reads, consent gating, owner spoofing, forged QC, private audit access and bucket policy. It is a test artifact, not proof the hosted service is secure. The cloud signed-upload endpoint, transactional ingestion/finalization, retention/delete cleanup and managed source polling still need integration before collecting cloud participant data.
