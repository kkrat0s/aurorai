# AuroraSense implementation rules

Read `goal.md`, `assets.md`, `plan.md` in full and inspect the approved wireframe before changing implementation. Those documents govern product scope, rights, science, and acceptance. Deadline: 2026-11-04 21:00 America/New_York.

## Build and ownership

- Build working, tested increments in one repository: Next.js/TypeScript web, Expo foreground phone recorder, Supabase managed persistence, Python science, bounded managed CI. No IaaS, background collection, or speech transcription.
- Keep three primary tabs, shared Live/Replay time, contextual Why and secondary Research drawers. Match the navy/teal/violet/amber wireframe direction without copying its invented readings.
- Update `docs/progress.md` with actual commands/results, limitations, blockers and next actions. Do not replace the approved specifications with another plan.
- No public deployment, paid service purchase, irreversible account change or external outreach without authorization. Never commit secrets, precise volunteer locations, private raw sessions, or assets without established redistribution rights.
- Parallel contributors own disjoint files; coordinate shared contracts before changing them. Preserve existing work.

## Scientific invariants

- Every chart and result has source, unit, frame, quality, time and provenance. Keep measurement, issuance, validity, availability and retrieval times separate. Unknown availability stays unknown.
- Phone axes are DEVICE-frame microtesla; 1 microtesla = 1000 nT. Record monotonic sensor time and UTC anchor, actual cadence, gaps and motion. Stop collection on backgrounding, consent withdrawal or explicit Stop.
- Synthetic fixtures are labeled SYNTHETIC / SYNTHETIC PHONE SIMULATION. Test-generated noise is not empirically measured phone noise. Never claim an actual historical phone storm or measured network improvement from simulation.
- QC, temporal alignment, geographical/environmental independence and professional references govern verdicts. A single device or co-located pair cannot establish regional disturbance. SUPPORTED never establishes visible aurora.
- Do not tune thresholds after viewing test outcomes. Freeze algorithm versions, seeds, event splits and availability assumptions. Report worse-than-baseline scores honestly.
- No fabricated NOAA historical issuance, invented confidence, extrapolated OVATION horizon, fake optical sighting, fake model call or fake physical-phone result. Missing/stale data must be visible.
- Broomfield is a candidate until archive checksum, schema, times, units, devices, cadence, overlap and license pass inspection. Keep restricted downloads ignored and never print precise participant locations.

## Agent and privacy boundaries

- Exactly the seven approved typed scientific tools; server-derived identities and roles, schema validation, bounded tool rounds/token use, deterministic authorization and append-only actions.
- The deterministic validator owns SUPPORTED/INCONCLUSIVE/REJECTED. Model narrative cannot override it. Invitations require existing adult opt-in and rate limits; never remotely activate sensors.
- Keep raw data in private storage with RLS. Export/delete and visible consent/stop are required. Fail closed when credentials or verified auth are absent.
- Clearly label deterministic scripted coordinator replay separately from a real Muse Spark 1.3 run. Verify current provider docs before enabling an adapter; keys stay server-side.

## Verification

- Run applicable type checks, lint, unit/scientific tests and production build. Test malformed/missing data, unit/time errors, contamination, co-location, leakage, forbidden tool calls and deterministic reset.
- Inspect rendered UI at desktop and phone widths where tools permit. Never equate compiled code, mocks, SQL text checks, or synthetic tests with hardware, hosted RLS or actual provider validation.
- Maintain reproducible commands, source manifests/checksums and precise next actions. No placeholders under filenames implying real measured achievements.
